## How to run

```
harness/grim-server/scripts/start_server.sh       # wait for "RCON running" in its server/server.log
harness/skeleton-server/scripts/start_server.sh   # the vanilla server, same
cargo build --release -p null-abilitycheck
./target/release/null-abilitycheck --server 127.0.0.1:25568 --rcon-port 25578 \
  --server-log harness/grim-server/server/server.log --account null_check --scenario all
./target/release/null-abilitycheck --server 127.0.0.1:25567 --rcon-port 25577 \
  --server-log harness/skeleton-server/server/server.log --account null_check --scenario all
harness/grim-server/scripts/stop_server.sh; harness/skeleton-server/scripts/stop_server.sh
```

**One command:** start both servers, then `scripts/full_suite.sh <prefix>` (e.g. `p31_full`). It builds the release binary, checks both servers are up (it does not start them), refuses to run beside another `null-abilitycheck`, runs vanilla then Paper + Grim with the flags above, and tees `<prefix>_vanilla.log` and `<prefix>_grim.log`. It ends with one summary (pass and fail counts, failed rows, Grim alerts in the run's window, time) and one macOS notification. Extra arguments pass through to both runs: `scripts/full_suite.sh smoke --scenario A1,AT`. Every row line ends with `[N.N s]`, and the runner prints `TIMING` lines after the summary line (total, modules slowest first, 10 slowest rows, RCON wait; fixed sleeps are not measured).

A scenario passes only when it passes on both servers (F5 §4.6). Run them one after the other, vanilla first: two suites at once stalled the client and drew Grim `Timer` alerts (2026-10-18). Each takes about 10 minutes. Rows print as they finish; if the bot stops answering, the runner prints a `RUN <module>_aborted` FAIL row and stops.

`--scenario A1,A5,...` runs a subset; `SHAPES_ONLY=<text>` reruns the shape rows whose name contains the text. Several runs can share the server with different `--account` names (the log check skips other `null_` accounts) as long as each scenario module uses its own test area (`Ctx::scene_in`).
