# Bench plan: remote server, load test, CPU density, crowd test

Moved from `OPEN.md` on 2026-11-02. Open; runs after `mine`, in the order `OPEN.md` gives.

**Bench, remote server.** Borrow the M5 MacBook Airs (family OK pending; backup: hourly VPSes). Add `host=` to `azbench` and a remote mode to `run_one.py`. Ladder 100–500 bots with 3 and 5 threads. Watch the Airs for throttling. **Load test on this machine (Allen, 2026-10-20), once the tree cutting is finished:** 100 bots fell trees with iron axes at once; log memory (RSS and footprint) beside CPU, tick gaps and server load. The 2026-10-15 bench measured about 0.75–1.3 MB per marginal bot, but with the bots near spawn sharing chunks and without Null's skills, belief and host. The felling test is the normal case (bots spread out, about 10 or fewer per chunk; Allen, 2026-10-20). **The same test is the CPU-density benchmark across machines (Allen, 2026-10-21; Mac, Pi, M5 Airs, VPS):** fixed seed, trees placed by RCON at fixed spots, the same tree, axe and start per bot, a fixed run length in game ticks (logs felled counted too). Ladder 10, 25, 50, 100 bots. Per step: client CPU-seconds per bot per game-second (process CPU time, apart from the server's), instructions retired per bot-tick (`/usr/bin/time -l` on macOS, `perf stat` on Linux; both machines are ARM64, so the counts should agree), p50 and p99 tick time and the knee (p99 over 40 ms), RSS per bot, and the server's tick rate (`/tick query`), so a slow server is not blamed on the bots. On the Pi the server likely saturates first: run the ladder until the server drops under 20 TPS and report that as the server's limit. The 100-bot run is on the Mac (Allen, 2026-10-21); the Pi runs only the low rungs (10, 25), enough to compare instructions per bot-tick between the two ARM64 chips. Pi pilot 2026-10-21: one harness bot used about 24% of a core (34 s CPU in 139 s, 54 MB RSS), but the harness does far more per tick than a working bot, so this is no estimate for the swarm. **A friend's swarm, same test (2026-10-21; Rust bot core, Node commander, MacBook Pro M4 Max):** 100 bots, 180.16 s wall, 67.24 CPU-s, 7891 logs, TPS average 24 (sped up), memory peak 596 MB (RSS, per the friend). If the 24 TPS held for the whole run: about 155 µs CPU per bot-tick, 0.0031 CPU-s per bot per game-second, about 6 MB per bot, 79 logs per bot. Not yet known: which processes the CPU and memory cover, how CPU was measured, how the wood was counted; Allen asked. **Crowd test for the upper bound:** 100 bots in one pen, all within 16 blocks, standing and then walking, plus a spawn rush (all join at once); report the per-observer entries per bot (patch 31), RSS, and the smoothing time per tick, and check that the 32-entry cap never drops a bot that could push.
