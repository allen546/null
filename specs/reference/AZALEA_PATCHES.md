# Azalea fork patches

**Record, started 2026-10-16.** These are the changes Null made to the Azalea fork at `~/Desktop/null-spikes/azalea`, on top of the 1.21.11 branch and its 38 cherry-picks. Patches 1–22 are committed and pushed to `null-main` (head `a30447e`, 2026-10-19); Null's `Cargo.toml` pins that head.

**Plan (Allen, 2026-10-16, revised the same day):** upstream asks for no AI-written contributions, so we don't send PRs. We keep our own public fork, [allen546/azalea](https://github.com/allen546/azalea), and expect many more patches. Rules:
- `null-main` (the default branch) is upstream's `1.21.11` + the cherry-picks + the bench timers + our patches, **one commit per patch**, each named `null patch: <n>-<name>`, so a patch can be read, reverted or rebased alone.
- Every patch gets a row in the table below (problem, fix, how it was found) in the same change that adds it.
- Mark each patch as a **bug fix** (upstream could take it) or **Null-only** (behaviour we need and upstream may not want). This tells us what a move to a newer upstream costs.
- Moving to a new Minecraft version means rebasing these commits onto upstream's new branch, so keep patches small and away from generated code.
- **Cite the source (Allen, 2026-10-17; in force from patch 11):** a patch that reproduces vanilla behaviour names the vanilla method in the row, for example "vanilla 1.21.11, Mojang names: `net.minecraft.server.level.ServerPlayerGameMode#handleBlockBreakAction`", and the Grim check it must pass, if any. Read the method in `~/Desktop/null-reference/` (`vanilla-1.21.11-src/` for client and server, `paper/` for Paper, `grimac/`; see its `MANIFEST.md` and [REFERENCE_SOURCES.md](../plans/REFERENCE_SOURCES.md)). Describe the behaviour in our own words; never copy code.

Patches 1-4 were found in the 2026-10-16 swarm duels (`null-node` processes of 8 or 20 bots each, on `skeleton-server`).
